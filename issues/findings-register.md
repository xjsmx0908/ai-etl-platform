## 明细

### UAT-001 数据接入下拉意义不清

- 类型：使用逻辑 · 级别：待定 · 状态：待复验
- 页面：`/data` · 角色：user / admin
- 复现：打开数据接入，查看知识空间或上传相关下拉，询问其业务含义。
- 期望：一眼能区分个人上传自动发布与受管空间需审批，并知道密级选项的权限后果。
- 实际：历史反馈认为「用户上传」下拉不知道有什么意义。
- 建议：复验后若文案已区分则关闭；若仍靠内部 ID 或术语，则改标签/帮助文本。

### UAT-002 可观测服务列表看起来不全

- 类型：使用逻辑 · 级别：待定 · 状态：待复验
- 页面：`/observe` · 角色：全部
- 复现：打开系统可观测，数服务卡片并对照 Compose 全栈。
- 期望：用户理解这是 query-api 聚合的主链路依赖，而不是全部容器。
- 实际：历史反馈认为 7 个服务不全，且不知道缺了什么。
- 建议：确认说明文案是否可见；若仍把 Kafka/PostgreSQL/MinIO 误当成故障，则调整文案或分组。

### UAT-003 问答过慢

- 类型：性能体验 · 级别：待定 · 状态：待复验
- 页面：`/qa` · 角色：全部
- 复现：对已发布文档提一个短事实问题，记录阶段耗时。
- 期望：有可接受等待，或至少能看到卡在检索还是生成。
- 实际：历史反馈要十几秒甚至更长。
- 建议：先记录首 token 与完成时间。若阶段条正常而模型慢，标为性能体验并与基础设施约束分开，不和「无反馈」混单。

### UAT-004 问答缺少阶段反馈

- 类型：使用逻辑 · 级别：待定 · 状态：待复验
- 页面：`/qa` · 角色：全部
- 复现：提问后观察按钮文案、阶段条和回答区，直到结束。
- 期望：类似对话产品，展示当前正在检索/生成/校验。
- 实际：历史反馈为一直阻塞。
- 建议：页面若已有 SSE 阶段条且真实更新，则关闭；若只在结束时跳变，则保持开放。

### UAT-005 问答未使用 SSE

- 类型：功能缺陷 · 级别：待定 · 状态：待复验
- 页面：`/qa` · 角色：全部
- 复现：提问时观察是否流式出现阶段或文字，而不是整段结束才返回。
- 期望：问答走 SSE。
- 实际：历史反馈认为没有使用 SSE。
- 建议：与 UAT-004 一并观察。若流式已通，关闭本单并在 UAT-004 记录体验是否足够。

### UAT-006 「日常巡检」问答无结果

- 类型：功能缺陷 · 级别：待定 · 状态：待复验
- 页面：`/qa` · 角色：user / admin
- 复现：定位该文档的空间、发布状态、权限，再用原问题提问。
- 期望：已发布且当前用户可见的文档能被引用；未发布则问答明确不可用，而不是静默找不到。
- 实际：历史反馈最新上传后问答没有答案。
- 建议：先区分未发布、空间选错、检索召回失败三类，再定级别。

### UAT-007 检索质量页意义不清

- 类型：使用逻辑 · 级别：待定 · 状态：待复验
- 页面：`/quality` · 角色：全部
- 复现：打开检索质量页，阅读标题、说明和指标。
- 期望：管理员/运维知道这是离线评测回归，不代表某一次问答分数。
- 实际：历史反馈不知道页面存在的意义。
- 建议：若说明横幅已足够则关闭；若普通用户也会进入且仍困惑，考虑菜单可见性或更短的一句话用途。

### UAT-008 发布中心 Run ID 与空治理字段

- 类型：使用逻辑 · 级别：待定 · 状态：待复验
- 页面：`/release-center`、`/agent` · 角色：admin
- 复现：以管理员打开知识发布中心，看主操作是否仍是输入 Run ID；再看责任人/生效日期为空时系统如何引导。
- 期望：主流程展示业务发布状态和审批动作；Run ID 仅作审计信息。缺治理字段时说明要去文档详情补齐。
- 实际：历史反馈存在 Run ID 输入框，且开始检查后多为责任人/生效日期不存在。
- 建议：主流程若已改版，关闭「输入框」部分，并把空治理字段引导是否足够单独结论。

### UAT-009 审计日志无分页无检索

- 类型：使用逻辑 · 级别：待定 · 状态：待复验
- 页面：`/audit` · 角色：admin
- 复现：打开审计日志，使用关键词、动作筛选和分页。
- 期望：管理员能检索并翻页，而不是只能看见一屏原始事件。
- 实际：历史反馈既没有分页也没有检索。
- 建议：若服务端分页和搜索已可用则关闭；若只有前端切片或不能按关键字搜，则保持开放。
