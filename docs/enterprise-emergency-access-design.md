# 企业紧急访问设计

## 状态与范围

提议评审（P2.5-G）。本文定义平台控制面的紧急访问（break-glass）保管、
审批、启用、使用、结束和演练契约；不创建真实账号、密钥或凭据，不配置外部
保管系统，不修改运行时代码，也不启用或部署生产紧急入口。所有人数、时限、
认证方式、网络限制和告警阈值均为 `Pending`，必须由指定企业责任人批准。

本能力只处理主 IdP 故障、身份配置错误或全部正常管理员无法登录时的平台身份
控制面恢复。PostgreSQL、审计存储或平台控制面不可用时必须执行独立的基础设施
灾难恢复手册；紧急访问不得变成数据库直改、shell、Kubernetes 或云账号后门。

## 已核实的当前状态

- 生产启用 OIDC 后，普通密码登录被关闭，平台只接受 `federated` 会话；当前没有
  独立紧急认证方式或路由。
- `BOOTSTRAP_ADMIN_*` 仅在空数据库首次启动时创建普通本地管理员；数据库已有
  任意用户后即不执行，且其 `local` 会话会被联邦生产策略拒绝。
- 普通 `admin` scope 同时包含查询、上传、Agent 和管理能力，范围过大，不能直接
  作为恢复权限模板。
- 登录审计当前是 best-effort；审计写入失败不阻止登录。这不满足紧急访问的
  “无持久审计则无权限”要求。
- 现有用户密码重置、用户停用和 `token_version` 只能撤销普通用户会话，不能表达
  独立审批、短期租约、操作白名单或保管人职责分离。

因此，bootstrap admin、普通本地用户、共享管理员密码和手工签发 JWT 均不是
企业紧急访问方案。

## 威胁模型与安全不变量

紧急访问既要承受主 IdP 的共同故障，也要防止其高权限被日常使用、单人滥用、
凭据泄露、重放或审计绕过。以下不变量不可由部署配置放宽：

1. **无常驻权限。** 保管材料可以常备，但未激活身份没有平台角色、scope 或内容
   访问权；权限只存在于获批且未过期的事故租约中。
2. **独立故障域。** 认证材料、审批和恢复工作站不得全部依赖主 IdP、普通管理员
   设备、同一网络路径或同一保管位置。
3. **多人控制。** 操作人不得批准自己的请求；批准人必须是互不相同的实名保管人，
   达到获批 quorum，且不能由一个共享凭据伪造多人同意。
4. **最小恢复权限。** 租约只授予事故所需的租户和恢复操作，不继承普通 `admin`
   scope，不允许知识内容查询/上传、发布、删除、Agent 执行或无关用户提权。
5. **失败关闭审计。** 租约创建、续期、撤销与关键状态审计在同一持久事务中提交；
   审计或租约存储不可用时不得签发或继续使用紧急凭据。
6. **短期且不可静默续期。** 租约具有绝对到期和空闲到期；延期必须重新说明理由、
   重新获得独立批准并轮换会话凭据。
7. **逐请求验证。** 每次操作都重新校验租约、操作、租户、操作者、会话、到期和
   撤销状态；签名正确但租约不可查时仍拒绝。
8. **可归责。** 共享恢复材料不能替代实名操作者和批准人身份；审计能把每个请求
   关联到事故、租约、会话和具体人员。

## 紧急访问接缝

新增深层 `emergencyaccess` 模块，而不是在普通登录或管理员处理器中加入条件分支。
其概念接口保持为三个操作：

- `Activate(ActivationGrant) -> LeaseCredential`
- `Execute(LeaseCredential, RecoveryCommand) -> RecoveryResult`
- `Close(LeaseCredential, ClosureReason)`

外部保管/审批适配器将其签名且单次使用的激活证明转换为
`ActivationGrant`。证明至少绑定事故/工单、实名操作人、互异批准人、批准时间、
目标租户、允许操作、not-before、到期、nonce 和策略版本；不包含长期私钥或
普通用户密码。模块负责验证 quorum、职责分离、重放、租约/会话状态、操作范围、
原子审计及通知 outbox。

激活证明不是 bearer 凭据。操作人还必须使用已登记且独立于主 IdP 的恢复认证器，
对平台生成的单次 challenge 和同一激活请求摘要签名；证明被截获后，缺少操作人
私钥仍不能激活租约。平台只保存公钥、认证器状态和验证结果，不保存私钥。

模块内部的 `EmergencyPrincipal` 使用独立的 `emergency` 认证方式和动作型能力，
不映射为 `admin` 角色。`Execute` 只接收类似 `identity.provider.rollback`、
`identity.session.revoke_all`、`identity.binding.repair` 或
`identity.health.read` 的已批准命令，并调用模块内部的受限恢复适配器。若平台尚无
安全的恢复动作接口，应另行评审最小适配器；不得借紧急访问开放全部现有管理路由。

每个命令携带唯一幂等键和规范化请求摘要。模块在副作用前持久化操作意图、授权
决定和审计；随后调用幂等适配器并持久化结果。PostgreSQL 内部变更尽量与结果审计
原子提交；外部 IdP 操作使用持久操作日志恢复不确定结果，禁止在意图持久化前调用
外部系统。相同键/摘要重试返回原结果，键相同但摘要不同则失败关闭。

## 保管与准备

保管对象是独立、抗钓鱼的认证材料或阈值签名份额，而不是仓库、环境变量、普通
密码管理器导出文件或个人手机上的共享 OTP。保管系统和验证公钥必须支持轮换、
吊销、离职交接及离线恢复；私钥/恢复码不得进入平台数据库、日志、浏览器或证据包。

至少准备相互独立的恢复路径，但具体数量和 quorum 保持 `Pending`。每条路径应有：

- 明确的业务所有者、实名保管人和候补保管人；
- 分离的防火/防篡改保管位置与至少两种不共享故障的通信路径；
- 指定的受控管理工作站、最小网络入口及时间同步要求；
- 无常驻平台权限的稳定恢复身份，以及可验证的公钥/证书生命周期；
- 失窃、人员离职、设备故障、策略变更和演练失败后的立即轮换流程。

网络允许列表、受控工作站和物理保管是补充控制，不能代替密码学认证、多人批准或
逐请求授权。现有 bootstrap 凭据和普通 SCIM/OIDC 用户不得转换为恢复身份。

## 启用、使用与结束流程

1. **声明事故。** 操作人记录不可使用正常管理路径的证据、影响范围、目标租户、
   请求动作、预计时长和回滚目标；计划演练使用独立的 drill 类型。
2. **独立批准。** 保管人在平台外验证事故和操作人，签署同一不可变请求。任一过期、
   重复、冲突、人数不足或操作人自批的证明均失败关闭。
3. **原子激活。** 平台验证证明，在同一 PostgreSQL 事务中创建唯一租约、初始
   会话、不可变审计和通知 outbox，再返回短期凭据。通知发送可异步重试，但不得
   丢失；通知系统故障不回滚已经持久化且可审计的本地激活。
4. **受限操作。** 只从指定工作站和入口通过 `Execute` 执行租约中的动作。每次
   请求先持久化幂等操作意图和允许/拒绝决定，再产生副作用并记录结果、关联 ID
   和时间；不记录秘密、原始外部 subject 或敏感内容。
5. **持续监控。** 每次激活、失败尝试、操作、延期和关闭都触发独立安全值班告警；
   未送达通知持续升级，不能被操作者自行确认关闭。
6. **结束与清理。** 目标恢复后立即原子撤销租约及全部关联会话，验证正常身份路径，
   轮换已暴露或策略要求轮换的保管材料，并确认不存在新增常驻权限。
7. **事后复盘。** 在获批时限内由未参与操作的责任人核对请求、批准、全量动作、
   结果、通知、撤销和轮换证据；未关闭复盘会阻止该路径再次用于非更高等级事故。

绝对到期、空闲到期和租约撤销必须自动使全部关联凭据失效。平台重启、并发请求、
时钟偏移和重复 Close 不得复活或延长租约。延期创建新的批准证据和租约代次，不能
修改历史到期时间。

## 演练与验收

演练使用预先批准的安全 canary 恢复动作，不修改真实用户权限或业务内容。至少覆盖：

- 主 IdP 不可用时，独立路径仍可在批准范围内恢复；正常 IdP 可用时的非事故请求
  被拒绝或按策略升级；
- 人数不足、自批、重复批准、过期/未来证明、错误租户、动作扩权、nonce 重放、
  签名轮换及已吊销保管人全部失败关闭；
- 审计/租约/操作日志故障阻止启用和操作；通知通道故障保留 outbox、升级告警且
  不丢失已持久化激活事实；外部动作超时通过幂等键和操作日志收敛，不能盲目重放；
- 租约绝对/空闲到期、手工关闭、并发操作和进程重启均立即阻止后续请求；
- 操作者不能查询内容或使用普通 admin/Agent/发布/删除能力，也不能把临时能力变成
  常驻角色、密码或绑定；
- 正常身份恢复、全会话撤销、材料轮换、权限差异检查及独立复盘形成完整证据链。

每次人员、保管材料、签名算法、策略、恢复动作、网络入口或相关平台代码变更后，
旧演练证据立即失效。P2.5-J 的生产身份验收包必须引用一份仍有效的 P2.5-G 演练
结果，但不得把真实保管人、位置、凭据、签名或恢复细节提交到本仓库。

## 实现切片

后续实现应拆为独立评审：租约/审计/outbox 数据模型；激活证明验证与保管适配器；
独立认证方式及逐请求策略；最小恢复动作处理器；通知、自动到期与复盘证据；最后是
隔离 staging 和生产 canary 演练。每个切片默认关闭，不复用普通密码登录，不扩大
`admin` scope，也不在本阶段配置真实保管材料。
