# 企业组到知识空间授权设计

## 状态与范围

提议评审（P2.5-H）。本文定义租户管理的“企业组 → 知识空间角色”授权契约；
不选择或配置真实 IdP，不启用 OIDC/SCIM，不导入真实组或成员，不修改运行时代码，
也不部署生产授权。同步时限、层级语义、审批人数、映射上限和告警阈值均为
`Pending`，必须由指定企业责任人批准。

本阶段只允许企业组授予现有知识空间内的 `reader`、`contributor`、`manager`
角色。原始组绝不能选择内部租户，不能授予平台 `admin/user/readonly` 角色、全局
scope、紧急访问或服务身份能力，也不能跨租户或跨知识空间传播权限。

## 已核实的当前状态

- `knowledgecatalog` 是查询和上传的授权权威；非平台 admin 必须在
  `knowledge_space_members` 中具有直接成员关系。
- 知识空间角色为 `reader`、`contributor`、`manager`。query 允许全部三者，
  upload 只允许 contributor/manager；平台 `admin` 当前绕过成员表。
- 当前仅有知识空间创建和列举路由，没有成员或组映射管理路由；manager 也尚无
  可调用的成员管理接口。
- OIDC 只解析协议身份声明，不请求或保存组；SCIM Users 明确拒绝 `groups` 和
  `roles`。平台会话和 `auth.Principal` 均不包含组。
- 用户创建/角色变更触发器会把平台角色映射到默认 `user-uploads` 直接成员关系，
  该历史兼容规则与未来组授权是不同来源。

因此，现有代码不存在可直接启用的企业组授权。向 JWT 增加 `groups` 字段或把组名
映射为平台角色都不满足租户隔离、撤权新鲜度和可审计性要求。

## 安全不变量

1. **内部租户先确定。** 用户必须先通过精确 `(issuer, subject)` 绑定解析到一个
   活跃内部用户和租户；组数据不能创建用户、选择租户或改变生命周期所有权。
2. **稳定组身份。** 映射键是 `(connector_id, provider_group_id)`；组 ID 必须稳定、
   不可重用且与连接器绑定。显示名、路径、邮箱、域名和大小写转换结果仅供展示。
3. **租户拥有映射。** 连接器预先固定一个内部租户，映射的知识空间必须属于同一
   租户。提供方组织、组路径或声明不能覆盖该约束。
4. **目录快照才是权威。** 经批准的组目录同步产生完整、有版本的成员快照；OIDC
   `groups` claim、ID token、access token 或浏览器数据不得直接授予权限。
5. **缺失不是空集。** 截断、省略、overage、分页不完整、版本倒退或同步失败的
   候选快照绝不替换上一个完整快照，也不能解释成“用户已退出所有组”。授权仅可
   在批准的陈旧窗口内继续使用上一个完整快照；没有完整快照或超过窗口则失败关闭。
6. **每次访问读取当前授权。** 组成员和映射不复制进长寿命平台会话。查询、上传、
   列举和管理操作通过 `knowledgecatalog` 读取当前内部快照；撤权在下一次请求生效。
7. **来源可解释。** 直接用户授权与组派生授权分别持久化。有效角色由固定算法合并，
   审计可说明是哪些映射提供了哪项角色，删除组授权不得误删直接授权。
8. **失败关闭。** 知识目录、组目录或有效授权查询不可用时，非 admin 访问拒绝；
   搜索索引、缓存或旧 token 不能成为授权回退来源。

平台 admin 的现有租户级绕过不由组产生。是否保留该绕过属于单独的平台角色策略，
不能通过本阶段映射扩大。

## 模块与接缝

### 组目录同步模块

新增深层 `groupdirectory` 模块，概念接口为：

- `ApplySnapshot(SnapshotCommand) -> SnapshotResult`
- `ResolveUserGroups(connectorID, externalSubject) -> GroupSet`

选定提供方适配器负责 SCIM Groups 或后台目录接口的分页、认证、速率限制和 payload
差异，并把数据转换成完整快照命令。模块验证连接器租户、稳定 ID、成员 subject、
版本单调性、完整性、幂等键和边界，再在一个 PostgreSQL 事务中更新组、成员、
同步状态和审计。原始 payload、token 和无关组属性不持久化。

成员必须通过同一连接器的稳定 external subject 关联到现有
`external_identity_bindings`；未知、跨连接器、跨租户、已删除或停用用户不获得
权限，并形成有界对账异常。组删除使用 tombstone，防止提供方重用 ID 接管旧映射。

### 租户映射模块

新增 `groupmapping` 模块，概念接口为：

- `Apply(MappingCommand) -> MappingResult`
- `List(MappingQuery) -> []Mapping`

映射记录包含租户、连接器、稳定组 ID、知识空间 ID、角色、状态、修订号、创建/
更新操作者及审计关联。写入时重新验证操作者权限、连接器租户、空间存在/活跃、组
存在/未删除和角色白名单，并把映射变更与成功审计原子提交。幂等请求相同则返回原
结果，请求键相同但摘要不同则拒绝。

租户 admin 可管理本租户映射。若未来允许 space manager 管理，只能操作自己已是
直接 manager 的空间，且授予 manager 需要另行批准；不能依靠待修改的组派生
manager 权限自我提升。具体审批矩阵保持 `Pending`。

### 知识目录有效权限

扩展现有 `knowledgecatalog`，但保持调用者接口仍为 `Resolve` 和 `List`。模块内部
一次读取直接成员和当前完整组快照对应的活跃映射，生成 `EffectiveMembership`：

- 无来源则拒绝；
- 同一空间存在多项允许来源时，按 `reader < contributor < manager` 取最高角色；
- 直接和组来源独立保留，删除一个来源后从剩余来源重新计算；
- 停用用户、空间、连接器、组、映射或不完整/过期快照均不参与授权；
- 结果携带策略/快照修订号和来源 ID，供审计与缓存失效，不暴露组显示名。

授权缓存只能保存短期派生结果，并绑定用户、租户、空间、能力、映射修订和组快照
修订。任一变更通过事务 outbox 失效相关键；缓存状态不可验证时绕过缓存读取
PostgreSQL，而不是沿用旧允许结果。

## 权威同步与撤权语义

优先使用选定提供方支持的 SCIM Groups，或经单独验收的服务器端目录同步适配器。
OIDC 组声明只可用于对账观测：由于 token 大小上限、overage、省略、嵌套组和登录
时点快照，它不能证明完整成员集合。

每个连接器维护 `last_attempted_at`、`last_completed_at`、源版本/游标、完整性状态、
计数和摘要。只有完整分页并通过一致性检查的快照才原子替换上一个已完成版本。
失败或部分同步作为独立尝试证据保留，不得把部分成员混入权威版本。授权是否继续
使用上一个完整快照由批准的最大陈旧窗口决定；超过窗口后组派生授权全部失败关闭，
直接成员授权保持独立有效。

权威快照确认用户移出组、组删除、映射停用或用户停用后，下一次授权查询立即撤销
对应来源。同步 SLA 衡量“提供方变更 → 平台完成快照 → 下一请求拒绝”，不能用登录
刷新时间替代。高风险 manager 撤权是否需要提供方事件推送加速保持 `Pending`。

## 嵌套组与冲突

默认建议只接受提供方明确给出的直接成员；是否展开嵌套组必须按连接器批准，并定义
最大深度、循环检测、动态组语义和可证明的完整性。适配器不得把不同提供方的 direct、
indirect 或 dynamic 含义静默混为一谈。

本阶段只支持允许式角色，不引入 deny 规则。多个允许来源取最高角色，算法稳定且
易解释；如企业需要显式 deny、职责分离或条件授权，应另立 ADR，不能通过特殊组名
隐式实现。映射冲突、孤儿组、未知成员、越界租户和角色升级均进入对账报告与告警。

## 管理、审批与审计

未来管理接口应位于知识空间资源下，例如组映射的 list/create/update/delete；具体
路径在实现切片确定。所有写操作要求高风险重新认证（P2.5-F）、幂等键和请求摘要，
并记录内部操作者、租户、连接器、组 ID 的不可逆摘要/安全标识、空间、旧/新角色、
修订和结果。不得把完整组成员列表、原始 external subject 或 provider token 写入
普通审计、日志、指标或浏览器响应。

创建 contributor/manager 映射、扩大目标空间或改变连接器属于提权。是否要求双人
批准、谁能批准以及是否允许 manager 授予 manager 均为 `Pending`。删除或降级映射
不能被审批延迟阻止；紧急撤权路径必须优先失败关闭并保留审计。

| SCIM Groups 或目录适配器的精确协议范围 | 身份工程 | Pending |
| 直接、嵌套和动态组语义 | 身份 + 安全 | Pending |
| 同步频率、最大陈旧窗口和撤权 SLA | 安全 + 身份运维 | Pending |
| 映射数量、组大小、分页和嵌套深度上限 | 平台 + 身份运维 | Pending |
| admin/manager 的管理与审批矩阵 | 租户责任人 + 安全 | Pending |
| contributor/manager 提权审批要求 | 安全 + 合规 | Pending |
| 组/成员 tombstone 与审计证据保留 | 法务 + 隐私 + 安全 | Pending |

任何空白决策都会阻止 P2.5-J 的真实提供方验收和生产启用。

## 迁移与回滚

1. 只读导入组和成员到隔离 staging，完成计数、摘要、分页、嵌套和未知成员对账，
   不创建映射。
2. 租户责任人为小范围 reader 映射逐项批准；以 shadow 模式比较组派生决定和现有
   直接成员，不改变实际授权。
3. 为指定 canary 用户启用 reader，再逐步启用 contributor/manager；每批次证明
   查询、上传、列举、管理拒绝、跨租户隔离和撤权 SLA。
4. 观察期通过后，才移除被明确替代的直接成员关系；保留来源记录，不能批量删除
   未匹配或手工例外授权。
5. 回滚停用新映射或连接器授权读取并恢复已记录的直接成员快照；不得回滚用户生命
   周期、外部身份绑定或平台角色，也不得继续使用陈旧组 token。

## 验收与负面测试

至少覆盖：

- 同名不同 ID、同 ID 不同连接器、组改名、删除/重建、ID 重用和 tombstone；
- 完整多页快照、重复/乱序版本、并发同步、部分页、overage、空列表、超限组、循环
  嵌套及动态成员，缺失/不完整数据不得扩大权限或误作权威空集；
- 未知/停用/跨租户用户、跨租户空间、错误连接器、非法角色、普通组推导平台角色
  和 raw OIDC claim 注入全部失败关闭；
- 直接与组来源的并集、多个角色取最高、删除单一来源、最后来源撤销、默认空间选择、
  query/upload/list/manager 能力及 admin 现有绕过保持一致；
- 同步/目录/数据库/缓存/outbox 故障、进程重启、并发映射、幂等重放和审计回滚；
- 用户移组、组/映射删除、用户/空间/连接器停用后的下一请求撤权，以及批准的端到端
  SLA、告警、对账和无敏感数据日志。

P2.5-J 必须用选定提供方保留完整组同步、映射、授权、撤权、overage/分页和回滚
证据。任何连接器协议、稳定 ID、嵌套语义、映射策略、同步窗口或相关代码变更都使
旧证据失效。

## 实现切片

后续实现应拆为：组目录数据模型与完整快照；选定提供方组适配器；租户映射模块及
管理接口；`knowledgecatalog` 有效权限合并；缓存失效、对账、指标和告警；最后是
shadow/canary 迁移与真实提供方验收。每个切片默认关闭，并保留现有直接成员和本地
确定性评测，直到明确迁移。

## 参考基线（非批准策略）

- [SCIM Core Schema RFC 7643](https://www.rfc-editor.org/rfc/rfc7643)：组资源、稳定
  资源 ID 及 direct/indirect 成员表达；规范本身不定义应用授权语义。
- [OpenID Connect Core 1.0](https://openid.net/specs/openid-connect-core-1_0.html)：
  身份声明传递基线，不把任意附加 claim 自动定义为授权策略。
- [Microsoft Entra 组声明指南](https://learn.microsoft.com/en-us/entra/identity/hybrid/connect/how-to-connect-fed-group-claims)：说明 token 组数量限制、overage 和声明省略风险。
