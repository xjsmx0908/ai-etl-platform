# 产品体验验收规范

最后核验：2026-09-09。

这是面向真实 Web 工作台的体验验收门禁，覆盖页面美观、使用逻辑和功能缺陷。
它不替代发布中心隔离栈、治理脚本或企业身份 staging；那些专项矩阵仍然
分别以 [`release-center-functional-acceptance.md`](release-center-functional-acceptance.md)、
[`governance-acceptance.md`](governance-acceptance.md) 和
[`enterprise-identity-production-acceptance.md`](enterprise-identity-production-acceptance.md)
为准。

发现问题记入 [`../issues/findings-register.md`](../issues/findings-register.md)。

## 目的

用当前运行中的产品，而不是只读代码或隔离脚本，确认三类角色能完成各自闭环，
并在使用过程中把问题写成可复现、可分级、可整改的记录。

完成标准：

- 每个角色路径和每个页面都有通过/失败结论。
- 登记册中 UAT-001～UAT-009 全部在真实页面复验。
- 新问题都有类型、严重级别、复现步骤和证据路径。
- 验收过程中不改产品代码；S1+ 才回写 [`backlog.md`](backlog.md)。

## 边界

做：

- 操作 `web/` 已暴露页面：登录、问答、文档、数据接入、可观测、检索质量、
  知识发布中心、用户管理、审计日志，以及 `/agent` 兼容路由。
- 覆盖 `readonly`、`user`、`admin`，机密/高风险场景再使用第二管理员。
- 记录美观、文案、空状态、错误态、权限提示、流程断点和真实缺陷。

不做：

- 不重跑发布中心 13 场景隔离栈，不把本验收当作治理或身份生产准入。
- 不把代码注释或历史修复说明当成页面已通过的证据。
- 不在巡检中途顺手改 UI/后端；先冻结清单，再按 S0→S3 分批整改。
- 证据中不保存密码、Cookie、Authorization 头或文档正文。

## 环境与账号

默认使用当前 Compose 全栈，Web 入口 `http://localhost:3100`。验收前记录：

| 项 | 要求 |
| --- | --- |
| 服务基线 | `docker compose ps` 中 query-api、web、parser、etl-worker 及检索依赖为 Up |
| 配置冻结 | 不在巡检中途改 `.env`、模型或索引参数 |
| 账号 | `admin`、第二管理员、可上传的 `user`、`readonly` |
| 空间 | 至少一个个人上传空间 `user-uploads`，至少一个已填用途的受管空间 |
| 样例 | 个人自动发布文档、普通受管文档、机密文档、待补齐治理字段的文档 |

四个账号在本轮创建或确认后写入当日证据目录的 `accounts.md`（只写用户名和角色，不写密码）。

## 角色路径

| 角色 | 必须走通 | 必须被拒绝 |
| --- | --- | --- |
| 只读用户 | 登录、选择授权空间、问答已发布公开知识、查看文档列表中的可见项 | 上传、发布审批、用户管理、审计、发布中心；直链管理页显示禁止而非空白数据 |
| 普通用户 | 个人空间上传后可问答；受管空间上传后保持草稿；文档检索与详情 | 机密上传、发布中心审批、用户/审计管理、自己批准自己的受管文档 |
| 管理员 | 创建/编辑受管空间用途、补齐治理字段、预审证据可读、单人批准普通文档、用户启停与重置密码、审计检索分页 | 用过期报告或变化后的 exact candidate 发布 |
| 第二管理员 | 对机密/高风险请求投出不同于发起人的第二票 | 为发起人代行自审；在第一票后把文档当成已发布 |

主闭环（管理员）：

```text
登录 → 选择受管空间 → 上传并填写治理字段 → 等待 ETL 完成
    → 知识发布中心查看预审 → 管理员审批 → 问答只引用已发布版本
```

辅助闭环：

```text
个人上传空间 → 处理完成自动发布 → 问答可引用
受管替换版本 → 旧发布继续可问 → 新版本独立预审/审批后切换
文档退役或删除 → 问答立即不再引用
```

## 问题分类

| 类型 | 记什么 | 示例 |
| --- | --- | --- |
| 美观 UX | 层级、密度、对齐、对比度、空状态、响应式、按钮拥挤 | 详情页操作区折行后分不清主操作 |
| 使用逻辑 | 控件存在理由不清、下一步不明、术语和业务对不上 | 上传页下拉看不出个人自动发布与受管审批的差异 |
| 功能缺陷 | 结果错误、状态不同步、权限泄漏、不可恢复 | 已发布文档问答找不到；草稿被引用 |
| 性能体验 | 可感知等待过长、阶段反馈卡住、超时无说明 | 问答超过可接受等待且阶段条不更新 |

严重级别：

| 级别 | 含义 | 处理 |
| --- | --- | --- |
| S0 | 核心闭环不可用，或出现跨租户/越权/数据丢失 | 立即停止后续巡检项，当天记录并升级 |
| S1 | 主路径失败，但可用其他角色或绕过 | 写入 backlog，优先整改 |
| S2 | 有替代路径，不影响发布/问答主闭环 | 纳入最近一批体验修复 |
| S3 | 抛光、文案、间距、非阻断的理解成本 | 可与相邻 UI 改动一并处理 |

## 页面矩阵

每页验收结束必须填写「结论」：通过 / 失败 / 受阻。失败项在登记册建单。

| ID | 页面 | 角色 | 检查重点 | 结论 |
| --- | --- | --- | --- | --- |
| PX-01 | 登录 `/login` | 全部 | 品牌区与表单层级、错误提示、密码可见性、OIDC/密码切换、已登录回跳 | 待执行 |
| PX-02 | 问答工作台 `/qa` | 全部 | 空间选择是否醒目并随请求提交；SSE 阶段条；引用可展开到文档/切块；草稿与未发布不得出现 | 待执行 |
| PX-03 | 数据接入 `/data` | user / admin | 知识空间下拉（个人自动发布 vs 受管需审批）；密级选项；治理字段何时必填；失败回显 | 待执行 |
| PX-04 | 文档管理 `/documents` | 全部 | 筛选、正文搜索、分页、角色可见范围说明、空状态 | 待执行 |
| PX-05 | 文档详情 `/documents/[id]` | user / admin | 治理编辑、发布态、版本替换、切块列表、删除/退役后问答变化 | 待执行 |
| PX-06 | 知识发布中心 `/release-center` | admin | 业务状态优先于 Run ID；预审证据、风险、建议、finding 引用；单审/双审下一步 | 待执行 |
| PX-07 | 兼容路由 `/agent` | admin | 与发布中心同一工作台，不出现第二套「输入 Run ID 开始检查」主流程 | 待执行 |
| PX-08 | 系统可观测 `/observe` | 全部 | 7 项主链路健康的含义；基础设施不在白名单的说明是否可读 | 待执行 |
| PX-09 | 检索质量 `/quality` | 全部 | 明确这是离线评测回归，不是当次问答评分；报告缺失时的说明 | 待执行 |
| PX-10 | 用户管理 `/users` | admin | 创建/编辑/启停/重置密码；非管理员直链禁止 | 待执行 |
| PX-11 | 审计日志 `/audit` | admin | 存在理由、关键词检索、服务端分页、详情展开、非管理员直链禁止 | 待执行 |

直链与菜单一致性也要记：管理员才看到发布中心/用户/审计；其他角色隐藏菜单且直链被拒绝。

## 执行节奏

| 阶段 | 动作 | 完成标准 |
| --- | --- | --- |
| D0 冻结 | 确认健康、账号、空间、样例文档 | 四个角色可登录；主链路 Up；样例身份不写进 Git |
| D1 复验旧账 | 逐条走下方旧问题清单 | 每条标记为已修复 / 仍存在 / 产品决策，并迁入登记册 |
| D2 角色巡检 | 只读 → 普通用户 → 管理员 → 第二管理员 | 主闭环可走通，权限边界无泄漏 |
| D3 页面深挖 | 按页面矩阵看空状态、错误态、文案、布局、响应式 | 每页有结论，即使是通过 |
| D4 冻结清单 | 去重、分级、归属、建议批次 | 登记册可执行；S1+ 已回写 backlog |

执行规则：

1. 先走真实页面，再对照代码确认根因；不以代码存在 SSE/分页实现直接结案。
2. 同一根因只建一条问题，其他页面用「另见于」引用。
3. 不确定是产品决策还是缺陷时，先记为使用逻辑，状态标 `待产品确认`。
4. 当天证据写入 `artifacts/product-experience-acceptance/YYYY-MM-DD/`。

## 通过标准

整轮体验验收通过，当且仅当：

1. 页面矩阵 11 项均有结论，失败项全部进入登记册。
2. 只读/普通/管理员主路径无 S0。
3. 问答不引用 draft、retired、未授权空间或未发布受管文档。
4. 管理员能从发布中心完成至少一次普通单审；机密路径能看出必须双人。
5. 旧九条均不再处于「待复验」。
6. 证据目录存在，且不含密钥和文档正文。

未通过时：保持登记册开放，不把专项脚本绿报当作体验验收通过。
