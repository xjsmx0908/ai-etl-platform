# P1.5 自动审核与 Gold 草案

## 审核边界

本轮对 P1.4 的 40 份私有文档和 128 条候选案例执行本地自动审核。工具先校验
原始文件路径和 SHA-256，再使用本地 `qwen2.5:1.5b` 独立判断文档类型、业务
领域、效力信号及问题/答案/证据一致性。所有正文、文件名和案例继续保留在 Git
忽略目录，未发送给外部模型。

自动审核不是业务签字。权限采用保守策略；低质量文档和未解决版本冲突自动
排除；制度、流程等声称当前有效的内容必须由业务责任方确认。输出明确标记为
`technical_gold_draft`，不能作为上线验收 gold。

## 聚合结果

| 项目 | 结果 |
|---|---:|
| 输入文档 / 候选案例 | 40 / 128 |
| 技术准入文档 | 27 |
| 低内容排除 | 4 |
| 版本冲突暂缓 | 2 |
| 效力待确认文档 | 7 |
| 机械证据校验通过的正样本 | 111 / 111 |
| 独立语义审核通过的正样本 | 16 / 111 |
| 安全负样本通过 | 17 / 17 |
| Gold 草案文档 / 案例 | 27 / 20 |
| 剩余人工确认 | 8 |

独立语义审核的失败信号可重叠：65 条问题不够自然，43 条答案不够完整，12 条
证据支持度不足。Gold 草案最终包含 10 条 lexical、1 条 semantic 和 9 条
safety-negative 案例。高词面重叠案例仍可验证精确检索，但不能用于证明语义
检索能力，因此必须按 cohort 分开报告。

## 日期规则确认

用户确认按最新日期处理 8 项待办。工具优先使用正文或文件名中的完整日期，
其次使用 PDF/Office 内嵌元数据；日期并列时拒绝猜测。本轮 8 项均成功解析：
7 份历史事项标记为 `historical`，1 组冲突选择 Office 内嵌修改日期更新的版本。
责任领域沿用本地审核建议，确认备注明确标记为日期规则而非制度台账验证。

确认后生成 `gold-candidate.json`，包含 35 份文档和 31 条案例：15 条 lexical、
1 条 semantic、15 条 safety-negative。所有确认已解决，但 provenance 仍保持
`business_approval_complete=false`；该候选可用于下一轮研发评测，不应直接作为
企业发布门禁。

下一步是自动重写被拒案例中的问题和参考答案。目标是建立至少 50 条自然
semantic/cross-document gold，并保留独立的 lexical 与安全 cohort；达到该规模
后再运行 reranker 和答案生成对照。
