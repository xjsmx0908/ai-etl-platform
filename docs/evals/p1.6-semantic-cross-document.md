# P1.6 语义与跨文档评测扩充

## 目标与边界

本阶段在 35 份已筛选的真实企业文档上扩充自然语义和跨文档案例，为后续
reranker 对照实验建立分层样本。正文、文件名、问题、答案和证据只保存在 Git
忽略目录，并且只调用本机 Ollama。产物是技术候选集，不是业务签字的验收 Gold；
`business_approval_complete=false` 保持不变。

## 结果

私有 `gold-candidate-v2.json` 共 70 条案例：

- semantic：30 条
- lexical：15 条
- cross-document：10 条
- safety-negative：15 条

语义扩充从 91 条可用候选开始。本地 `qwen3:4b` 执行 86 次改写，57 次因字面
重合或关键事实门禁被拒绝，29 条新增案例通过机械校验及 `qwen3:1.7b` 独立
复核。跨文档案例仅组合相同业务域的不同文档，标准答案由已审核的单文档答案
确定性组装；模型只生成自然问题，随后复核是否确实使用全部来源。

## 完整性检查

- 35/35 来源文件 SHA-256 与清单一致。
- 40/40 semantic 和 cross-document 案例具有私有逐字证据绑定。
- 10/10 cross-document 案例要求至少两个有效来源。
- semantic 与证据的最大重合度为 53.85%，cross-document 为 50%。
- 通用数据集校验与 P1.6 专用证据校验均为零错误。
- 评测执行器现要求跨文档案例同时检索并引用所有 `required_doc_ids`。

## 下一门禁

使用同一数据集和上传映射，对 no-rerank 与 `auto` rerank 各运行至少三次。
按四个 cohort 分别比较 Recall@5、全部来源命中率、引用完整率、关键事实覆盖、
拒答、grounding、延迟和方差；达到预先定义的非退化门槛后再决定默认策略。
